# Leg-3 candidates DROPPED tonight — recorded so they are not re-derived

A dropped candidate is not a silent omission. Both below were carried through the full
reviewer → adversary → judge gate and refused on evidence.

## N1 — `check:backlog-refs` (a gate requiring every backticked code reference in the backlog to resolve)

**Proposed** to end the pattern "a backlog entry's own prose misstates the mechanism of the code it
describes, so a fix derived from the entry is wrong."

**The pattern is real but is NOT new.** It already has two durable memory homes
(`backlog-prose-decays-verify-against-head`, `backlog-item-states-invariant-not-fix-mechanism`) and
the 2026-07-24 friction entry at `open-bugs.md:554-561` already cites the first by tag. Presenting
it as a new pattern is the doubling leg 3 exists to prevent.

**The claimed count did not survive.** Reviewer said 4 dates / 8 instances. After the adversary
read each: ~3 clean dates / ~6 instances, and 4 of the 6 land on a single date (2026-07-24) which
was itself a backlog clear-out lap whose explicit purpose was finding such entries — a selection
artifact, not four independent recurrences. Two claimed instances were refused outright: the
2026-07-19 memory is dominantly a *staleness* pattern, not mechanism-misstatement, and counting
tonight's own reviewer error as evidence for tonight's own proposal is circular.

**The mechanism was refuted on measured data**, not on judgment. The adversary ran both halves over
`docs/backlog/*.md` at HEAD:

- **Path half:** 120 backticked `src/`/`scripts/`/`tests/` citations, **1 flagged, and it was a
  false positive** (`scripts/{audit,remediate}/postinstall.mjs` — brace notation; both files
  exist). **Zero true positives across the entire backlog.** The gate would ship as a pure-noise
  net guarding a defect that is not currently present.
- **Identifier half:** 591 backticked identifier candidates, 40 not findable — a ~85% false-positive
  rate on inspection. The bulk is legitimate: external vocabulary the repo does not own
  (`finish_reason`, `ERR_MODULE_NOT_FOUND`, `core.quotePath`, …) and — decisively — 11
  deliberately-not-yet-existing symbols in `forward-tracks.md`, the file whose entire purpose is
  proposing symbols to build. The gate would make it impossible to name a symbol you are proposing.

**And the fatal objection:** every *strong* instance of the pattern (FLW-COR-003's lease semantics,
`analyzerDeps`' phantom `npm install`, unplaceable-node's "blocks the rest of the run", the advisory
that "did not trigger") cites a path that **exists** and an identifier that **is findable**. The
gate catches **0 of those 4**. It would only catch the staleness class — which measures at zero
today.

**Verdict: do not build.** If the pattern is to be mechanized, the target is paraphrase-of-mechanism,
which is not decidable from content. The existing lever is the one already in place: the entry
template's "link the primary record rather than retell it", plus the size budget that makes
retelling expensive.

## N2 — requiring every `durable-traps.md` entry to name its guard or carry an `unmechanizable:` marker

**Held back, and both agents agreed.** Three reasons:

1. It is already project doctrine (`CLAUDE.md` → *Auditor-agnostic robustness*;
   `[[enforce-robustness-in-tooling-not-host-discretion]]`), so proposing it is a third copy.
2. The `unmechanizable:` marker is **self-certified** — an agent can mark anything to clear the
   ratchet, which makes the gate performative. No clean solve was found.
3. Its own countermeasure would be prose, which is self-refuting. The genuinely actionable move for
   this class already shipped and is the right generic one: **promote the advisory to a refusal**
   (`5fc913a8`, `[[an-advisory-that-fires-and-is-read-past]]`).
