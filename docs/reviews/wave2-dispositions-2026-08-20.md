# Wave-2 remediation dispositions — close-phase backfill record

## Why this record exists

The remediation run's close phase must join every approved finding id against the
outcomes contract with a complete file + line + mechanism evidence triple. The
host-result envelope has no channel to carry a finding's disposition or its
evidence triple back to run state, so each wave-1/wave-2 work item's worker
recorded that information only in its own worker summary (session-scoped
scratchpad, since expired) and in its commit body. Nothing in `.audit-tools/`
persists it. This file is the durable source the close phase's coverage join
backfills from until the result envelope can carry the triple itself.

Every disposition and evidence triple below is transcribed as the owning
worker actually stated it — nothing here is inferred or reconstructed. Where a
worker did not state a location (no line number, no mechanism), the
corresponding cell says so explicitly rather than being filled in.

`fixed` / `fixed → resolved` both mean the finding was verified violated at
HEAD and closed; `→ resolved` is the persisted-outcome status a few workers
named explicitly. `refuted-against-HEAD` means the finding's mechanism was
checked against HEAD and does not hold; it persists as the outcomes contract's
`refuted` member, never `verified_already_fixed`.
